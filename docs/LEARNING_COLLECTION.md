# DaguaBC 本地学习记录规划

## 本次交付：0.2.0

先可靠收集，再整理训练集，最后做有对照的模型试验。当前仅完成收集，不启用训练、不上传视频或记录、不自动替换模型。

- 每个工程的 `project.db` 增加 `learning_records`。用 SQLite 触发器与业务修改在同一事务中写入；写入失败向调用者返回错误，事务回滚后不会留下假成功的记录。
- 记录候选、审核、片段范围、球员/标签、视频关联、篮筐、项目信息和导出记录的数据变更前后。只读浏览、播放、无变化的保存及审核计时更新不算新的数据变更。
- 每条记录有顺序号、UTC 时间、结构版本、实体类型/ID、操作和上下文；候选/审核上下文包括视频路径及指纹、分辨率/帧率、候选时刻/范围、模型版本及原始证据、篮筐设置。没有复制视频，不需要重新分析。
- 现有工程在首次打开时为已有候选建立一次 baseline，保留当前状态；不推断历史点击。旧记录没有候选外键，重新分析替换候选和清理缓存都不会删除它们。删除整个工程会连同记录删除。
- 记录数据库变化而非鼠标点击，一次批量操作或重新分析会产生多条记录；自动生成和人工行为都保留，不能将记录总数解释成已标注样本数。
- 所有记录 `label_policy=observation_only`。保留/排除只表示剪辑选择；手工补漏是重点待核验案例，不自动升级为进球真值。后续应结合审核日志、来源与修改顺序整理样本。
- 设置中显示当前工程变更数、起始快照数，可刷新；无工程时显示打开项目提示，读取失败明确提示。协议 `get_learning_summary` 返回统计，不导出数据。

## 后续阶段（尚未实现）
